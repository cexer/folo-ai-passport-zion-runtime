# Runtime 优化及兼容性背景记录

## Passport OS 接入检查点（2026-10-27，进行中）

选样改用官方累计 `sort=hearts` 接口，已核对公开 `hearts` 字段降序；只有点赞排序
不可用时才退到下载量。快照、队列位于 `diagnostics/community/popularity/`。
438 本次使用独立的完整仓库 `manchunx7-bit/passport-os`，版本 `b70879b`，不是历史
voice 单模块仓库。业务源码、资源未修改，编译单元见 `examples/link-apps/passport-os/`。

原源码编译暴露的通用要求：

- 组件自己的头文件必须优先于宿主应用头文件，否则其 `ui_pixel.h` 会误选 ZION UI。
  构建适配器已修正优先级。ADC 轮询应用显式声明输入方式，不再被未使用的回调枚举顺序拒绝。
- 启用真实 PM、tickless idle、TJPGD、内存文件系统。SPIFFS 使用必需的包能力位，旧基座
  会拒绝；旧包默认仍是 FAT。复用存储时检查文件系统子类型，不把 SPIFFS 冒充为 FAT。
- 原 Muse TLS、Opus 包装还需要接管 SDK 内部调用，只有插件局部 `ld --wrap` 不够。
  有类型的共享分发器暂存已验证 ELF 函数地址，在可执行缓存提交后激活；`__real` 导入
  绕过分发。重试前清除失败加载的暂存地址。测试覆盖延迟激活、无递归委托、拒绝 ELF
  不发布函数。未增加业务修补包装。
- GCM 桥只引入 IDF 6 真实 TF-PSA 头及结构，显式启用私有声明，不复制 IDF 5 上下文。
  加密头文件纳入精确基座 ABI 指纹。
- 原自定义音频会话、内存诊断私有编译，底层仍是共享 SDK 驱动。显示主亮度、电源和
  同步电量轮询、日志接口复用现有硬件所有者。

编译阶段 ELF 有 4,237 节、437,692 字节代码、101,542 字节可写状态；最大原始对象
是连续的 49,152 字节音频工作区。这是 ELF 测量，不代表设备加载通过。200 个缺失导入
已由真实实现完成链接，初版 APP 超出 factory `0x6890`；随后蓝牙控制器代码搬入 Flash
还需空间。当前 factory 为 `0x2D2000`，pool 0 起点 `0x2E2000`、大小 `0x74000`。
身份分区 `0x356000` 和 pool 1 不动。这是已授权的新测试布局，不是旧目录的无损升级。
原 2 MiB SPIFFS 预留在存储分配阶段安装失败；测试配置改为 512 KiB，保留全部原资源，
但可上传的名片容量减少。原容量失败证据单独归档。

原生对照：原 APP 约 3.95 MB，原写入地址会覆盖身份区，因此将完全相同的 APP 放到
`0x360000` 执行，身份区下方保留原有 2 MiB SPIFFS 容量。抽屉、秒表计次/暂停/清零、
方块启动/移动/旋转及设置已真机通过，并检查截图。身份字节读回与测试前一致。
这是移动分区的原生对照，不声称已在 `0x10000` 安全刷入原前缀。

原内联诊断通道先丢失 TX 确认，后续完整异常显示边界对应 1536 字节的
`xIsrStack`（`0x3fc8f7b0..0x3fc8fdb0`），当时被中断任务为 `ser_cmd`。
不能仅凭任务名认定其自身栈溢出。诊断确认改为有界、整条 USB 写入；stdin 与原始
USB 共用分流；解析、截图转交独立 6 KiB 测试工作任务。相同步骤随后通过。
队列上下文、FIFO、满队列、超时和初始化回滚均有主机测试。

**MEM-08 / 438：**用每节一位的位图替代重复扫描，并在加载时让出调度。
原分配前扫描触发 IDLE 看门狗；后续真机约 426 ms 到达元数据阶段，未触发看门狗。
同时启用 USB 连接时禁止自动轻睡的锁，适配子应用主动开启 PM。

**MEM-09 / 438：**蓝牙代码移入 Flash 后，49,179 字节的工作区已能分配。
下一处实测失败为 50,844 字节临时映射表：总空闲 74,592，最大连续块 24,576。
映射表先尝试整块，失败后按 32 节分页（RV32 每页 384 字节），进入应用前全部释放。
预留暂存区后最大连续块仅 2,688 字节，早先的 256 节分页仍放不下。
真实 ELF 重定位和逐处分配失败回滚主机测试通过；旧设备已通过 133 页映射
加载全部 4,237 节并进入 Passport OS。不拆分应用对象，本例改变基座，连续计数仍为零。

**MEM-10 / 438：**交错分配时，4,804 字节暂存请求遇到仅 4,608 字节的最大连续块。
改为在元数据分配前预留最大暂存节（11,228 字节），各节复用，进入应用前释放。
旧设备随后到达 Boot Complete 并通过秒表流程；收音机仍会因自身堆内存检查主动重启整理内存。

**MEM-11 / 438：**旧回退路径为 698 个可写节分别分配内存。
改为小对象合并到有限大小的内存块、大对象优先分配；失败时只在原对象边界拆分。
真实 ELF 主机测试及分配失败回滚通过。新连接的 C3/8MB 设备上分配块降至 16；
启动时空闲/最大连续块为 30,696/12,800 字节，秒表、运行中俄罗斯方块、设置主流程
完成后为 44,476/17,408。旧设备优化前启动时为 9,700/7,168；这是跨设备比较，
不是同设备受控 A/B。实际 LCD 截图及上/下/短按 OK/长按 OK 流程通过。
证据：`diagnostics/community/passport-os/report.json`；对应产物：
`dist/community-link-validation/passportos-packed-arenas/7fc7dd1f5611`。
这不是对应用文件大小设置限制。

每项基座改动记录触发应用、实际故障、通用修正及证据。应用专属修正不算公共能力；测量值仅适用于对应构建。

## 内存优化

| 编号 | 触发应用及故障 | 通用改动与证据 |
| --- | --- | --- |
| MEM-01 | Octo Radio 的 ELF 有 1193 个节，临时工作区 52,492 字节超过最大块 45,056 字节 | 借用已验证的节头，精简映射表仅需 14,316 字节。代码逐节写入 Flash，暂存峰值实测 11,572 字节，避免把 119,076 字节代码常驻 RAM。见 `main/zion_elf.c`、`main/zion_elf_host.c`。 |
| MEM-02 | Octo Radio 的 MP3 请求 8192 字节，最大连续块仅 7680 字节 | 将需要重定位的不可写 PROGBITS 放入 DROM 缓存；模块 RAM 从 29,732 降到 22,276 字节，节约 7456。可写数据及构造数组仍在 RAM；旧包空间不足可退回 RAM。宿主测试覆盖缓存预算、重定位及失败清理。 |
| MEM-03 | MEM-02 后 Octo Radio 的 Wi-Fi 仍有 1700 字节分配失败 | 先分配持久模块状态和映射，再分配临时元数据，减少空洞被夹住。与 MEM-04/05 合并真机验证，不声称单独测得收益。 |
| MEM-04 | Octo Radio 内存紧张，而显式 SDK 帧工作区从未使用 | 80 块图像描述工作区首次使用才分配，C3 静态 RAM 节约 2716 字节。原生 LVGL 真机已验证；改动后的显式 SDK 帧绘制尚未重新验证。 |
| MEM-05 | Octo Radio 内存紧张，目录重复保留完整包头 | 目录仅保留自己拥有的名称和键，节约 912 字节；整个运行期间字符串有效。 |
| MEM-06 | Bathroom Reader 的包能放下，却因预算过大被拒绝 | 按实际安装占用而非悲观填充计算：1,695,744 字节的包可放入 1,703,936 字节空隙，旧估计为 1,708,032。这是 Flash 计量，不是 RAM。 |

MEM-01 至 MEM-05 的[测量和边界](runtime-memory.zh_CN.md)，证据位于
`diagnostics/community/octo-radio/memory-final-progress/`，宿主批次 `60cd2e31d2ab`。
最终 25 秒稳定窗口内，静音 I2S 前进 1,049,472 字节，无分配失败。
原应用启动时从 8 KiB 抖动缓冲降为 6 KiB 的回退仍存在，不能称为已消除。

## 测试工具及结果解释

- 四子棋横屏一行 320 像素需要 1280 个十六进制字符。SDK USB 写入是整条入队或返回零，
  原有 1024 字节 TX 环不能容纳一行。`main/zion_test_capture.c` 改为每段 256 字节像素，
  保持原 TX 环大小；重建时拒绝缺块、冲突及重叠。宿主 `5f67f4cdc172` 已完整抓到真机
  320×240 画面，模拟器原始 RFC2217 字节流也通过。CLI 串口“预览”会截短长行，不能据此重建图像。
- 查看四子棋证据期间 COM5 曾消失。源码存在菜单闲置 60 秒休眠，但用户也提到移动 USB 接线，
  随后明确表示原因不确定；历史断连不能确定归因于休眠或接线。
  `tests/firmware/sleep_guard.c` **仅在 DeviceTest 测试包**中将最终深睡改为重启，
  独立/运行时测试均使用；正式包仍用真实 SDK 休眠。实际包装函数已通过“不返回且复位”宿主测试，
  ELF 导出该包装函数，真实 `esp_deep_sleep_start` 未链接。此类测试明确不验收休眠电流及硬件唤醒。
  防失联宿主已构建，仍需设备实体唤醒后才能替换当前睡眠中的固件。
- Liquid Glass 独立模拟器进入其 GPIO0 恢复分支，而 `0x700000` 没有出厂预置的恢复镜像，
  该独立模拟运行不算通过。原应用在另一份 ZION 模拟器宿主中已执行，不代表验证了真机独立启动。
- SDK 5→6 API 改名及保留的上游编译警告写入构建配置/清单，与应用专属修正分开记录。
- `tools/record-clean-streak.py` 保存源码/配置、bootloader、分区表及宿主身份快照。
  `tests/test_clean_streak.py` 拒绝模拟器、未检查画面、源码改动及应用专属修补包装，
  并验证失败会清零。候选仓库源码均保持不变。

## 新一轮无需改基座连续通过

2026-10-27 从 **0/3** 开始，历史成功不倒计入。一款一款拉取复杂社区应用；
计数须业务源码不变、基座身份一致，并在真机通过启动、主流程和按键。
记录源码/构建哈希、导入符号、截图、日志及未验证项。
需要修改基座代码、导出或配置时，计数归零。
专属应用包装和构建前排除单独记录，不计入干净通过。

本轮状态以 `diagnostics/community/clean-streak/state.json` 为准。
