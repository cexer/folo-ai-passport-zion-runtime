# 运行时内存实测

## 通用加载器优化（2026-10-27）

应用业务源码保持不变。以下优化不判断应用名称或编号，适用于插件通用路径：

- 将需要重定位的非可写 PROGBITS 放入可读的 Flash 缓存。可写数据、BSS、
  初始化函数数组仍在 RAM，其余不可变数据继续直接映射原始文件。
  旧包缓存不足时回退 RAM，新包会预留代码和只读数据两部分缓存。
- 先分配长期存活的插件状态与映射，再分配临时段表，减少长期对象夹在临时空洞之间的机会。
- 显式 SDK 的帧工作区改为首次使用时分配；原生 LVGL 应用不再承担其 2,716 字节静态占用。
- 运行时目录仅保留名称和 key，避免重复保存完整包头，再减少 912 字节静态 RAM。

匹配版本的 Octo Radio 中，需要重定位的只读数据为 7,456 字节，插件 RAM 数据区
从 29,732 字节降至 22,276 字节。两处静态优化合计减少 3,628 字节，未扣除加载器
新增管理字段，也未计算分配器布局影响；其他插件的收益可能不同。

最终插件在 COM5 通过 MP3 解码、切台、暂停/恢复、动画和设置主流程。
25 秒稳定观察窗口内，真实静音 I2S 计数增加 1,049,472 字节，没有内存申请失败。
原应用会先申请 8 KiB 播放缓存，失败后回退 6 KiB；该启动阶段的预期申请失败仍保留。
它不同于原先的 MP3 申请失败，也不同于中间版本出现的 Wi-Fi 申请失败。

证据位于 `diagnostics/community/octo-radio/memory-final-progress/`。
独立版使用 ESP-IDF 5.5.3，宿主使用 6.0.1，不能直接将两者剩余堆差值当作框架开销。
实际音质、公网电台及长时间运行仍未验证。

本文 ESP32-C3 / 8 MiB 真机数据取代之前内置测试示例的报告。实验宿主只内置小智；
画廊从外部 ZPK1 包安装，RV32IM ELF 在 RAM 中执行。正式 ZION 仍通过重启引导完整子固件，
不会把管理器的堆分配保留在子固件内。

## 画廊对照

两种运行方式解码同一个 158,140 字节的 FGA1 动画，240×320 RGB565 画面占 153,600 字节。
数值来自 COM5 真机日志。原版源码：[PhoenixZHC/folotoy_gallery](https://github.com/PhoenixZHC/folotoy_gallery)，
提交 `00cbde9d2c9f7998f1690e44c7dcc8ed21cbb63f`。

| 阶段 | 剩余堆 | 最大连续块 |
| --- | ---: | ---: |
| 独立画廊播放中，开启热点/HTTP/FAT | 24,400 B | 16,384 B |
| ZION 外部画廊，尚未分配 ELF/画面 | 168,456 B | 65,536 B |
| ZION 外部画廊播放中 | 9,732 B | 800 B |

独立画廊静态预留 150 KiB 像素缓冲；ZION 启动插件后动态申请，所以不能直接比较表格前两行。
播放时相差 14,668 字节，也不等于框架净开销：两边 SDK 版本和配置不同，独立版还包含 FAT、
HTTP、音频播放器和 Wi-Fi；当前插件只移植了 FGA 解码、调度和按键交互。

独立测量版增加内存日志，通过原有媒体存储 API 写入同一动画。为了保留设备身份和已安装插件，
测试 FAT 分区移到 `0x360000..0x7F0000`。它不是与官网发布包逐字节一致的 BIN。
测试后已恢复 ZION 的引导程序、分区表和 APP；未整片擦除或写入身份区域。

## 分配与归属

进入离线插件时删除旧管理界面、停止并释放蓝牙、退出安装/网络任务、释放队列并关闭 Wi-Fi。
8 KiB 栈的 USB 安装任务退出，保留 2 KiB 栈的 USB 控制任务，可查询内存，并明确拒绝玩法运行中安装。
下次开机回到列表仍支持 USB 安装。ROM USB 刷机不依赖这些任务。
共用显示/LVGL、按键、电池、存储及当前插件继续运行；小智保留联网能力。

分配画面前，静态数据、RAM 指令、系统/驱动任务、LVGL 缓冲和任务栈已经占据部分 RAM。
测量时宿主 map 中 RAM 代码为 97,108 字节，`.bss` 为 44,320 字节，`.data` 为 20,985 字节；
这是后续自适应画面数组加入前的数据，不是最终版本的精确布局。大部分固件代码和只读资源仍映射在 Flash。

固定 15,360、7,680、3,840 字节的图像块都曾在总空闲内存仍足够时分配失败。
现在按可用连续块自适应分配高度，使用一个 LVGL 绘制对象。真机成功运行实际使用 35 块；
旧模块日志的 `tiles=5` 是过时的固定文本，不是实际分配数。仍保持 RGB565，没有降低像素精度。

## 验证边界

Build：测量版独立固件和实验 DeviceTest 构建 PASS。
Host tests：七组针对性测试 PASS。Device tests：外部 ELF 加载、FGA 完整帧/差分帧播放、
串口注入暂停/继续、长按 OK 不重启、内存观测、USB 控制及运行中安装拒绝 PASS。
最大连续块仅 800 字节，仍是明显限制。

未验证：实体按键手感、摄像头观察屏幕、音质、网络/语音并发、长期碎片情况、生产全新构建，
以及通过正式 ZION 完整安装独立画廊。继承的全量门禁仍受导入文档的双语检查阻挡，不能将局部通过写成产品验收通过。

数据和固件哈希位于 `diagnostics/gallery-memory-comparison/`，原生运行日志位于
`diagnostics/device-external-test/`。旧 `runtime-final-report.json` 和 0.2.0 产物只描述已被取代的内置示例。
